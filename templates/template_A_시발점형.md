# 템플릿 A_시발점형 — 재사용 규칙

> 뼈대: 『시발점』식 **상황·직관 → 유도 → 정의 → "정리하면" 박스 → REMARK → [예]** 의 촘촘한 계단.
> 보완: 시발점에 없던 **풀이(접기)**, **장 끝 요약·오개념 체크**를 반드시 붙인다.
> 다른 형식(개때잡)의 장치는 이 뼈대를 해치지 않는 범위에서만 보조로 쓴다(풀이 근거 주석 `← 이유`, 자문자답 1회, 표준 도식 재사용).

---

## 1. 장 전체 구조

```
# 제N장 장제목
  [장 첫머리]  ① 이 장의 개념 흐름도(텍스트 화살표 지도)  ② Theme 목록표(Theme ↔ PPT 절 ↔ 쪽)  ③ 이 책 읽는 법 3줄
## Theme k. 주제명        ← PPT 절(7.1, 7.2 …) 하나 = Theme 하나. 보충자료는 별도 Theme.
  [Theme 머리]  지도 재등장(현재 위치를 **굵게** + ◀ 현재 위치)
  ### k-1. 소단원          ← PPT의 번호 소제목(1. 2. 3.) 하나 = 소단원 하나
    #### 1) 세부 항목      ← 필요할 때만
  ### Theme k 예제         ← 직접 푸는 문제 (풀이·답 접기)
  > Note (필기 칸)
## STEP UP (Theme a~b)   ← 2~3 Theme마다 통합 문제 3~5개
## 장 끝 정리              ← ① 박스 모음 요약 ② 판단 흐름도 ③ 수치표 모음 ④ 오개념 체크(OX) ⑤ 원본 표기 확인 목록
```

- Theme 번호는 장 안에서 1부터. 다른 장에 적용할 때도 같은 체계.
- 각 소단원 맨 위에 위치줄 한 줄: `> **위치** Theme k · 소단원명` (세로 위치띠 대체).

## 2. 소단원 블록 순서 (고정)

| 순서 | 블록 | 마크다운 표기 | 규칙 |
|---|---|---|---|
| ① | 위치줄 | `> **위치** Theme k · 소단원명` | 1줄 |
| ② | 도입(상황·직관) | 평서문 2~5줄. 첫 줄은 PPT 속 상황 또는 "왜 ~일까?" 질문 1개 | 정의로 시작 금지. PPT 범위 밖 사실 금지 |
| ③ | 유도 | `$$\begin{aligned} … \end{aligned}$$` + 줄마다 `\quad\text{← 이유}` | PPT에 있는 식 변형은 하나도 생략하지 않는다. "식 한 줄 + 의미 한 줄" 교대 |
| ④ | 정의 서술 | "이런 것을 **용어**(영어)라 한다." | 새 용어 첫 등장만 굵게 |
| ⑤ | [참고] | `*[참고]* …` 1~3줄 | 기호 읽는 법, 영어명, 표기 관례 |
| ⑥ | 정리 박스 | "이상을 정리하면 다음과 같다." 한 줄 뒤 인용 블록 `> **[정리] 제목**` + ❶❷❸ | 공식·조건·성질만. 박스 마지막 줄에 출처 `[N장 p.x]` |
| ⑦ | REMARK | `**REMARK n. 질문/주장형 제목**` + 들여쓴 본문(인용 블록 아님) | 소단원당 1~4개. 주제: (a) 왜 그런가 (b) 기호·값의 의미 (c) 흔한 오해 — "~가 아니다"로 부정 (d) 앞 단원과의 연결. 강사 말투("~해 두자")는 여기서만 |
| ⑧ | [예] | `**[예 k-m]**` 문제 → `<details><summary>풀이</summary>` → `<details><summary>답</summary>` | PPT 예제는 모두 여기(원래 번호 병기: "원본 예 7-4"). 1~2단계 적용. 풀이는 세로 정렬, 결론 줄 `∴`, 줄 끝 `← 근거` |
| ⑨ | 출처 | 블록 끝 `[7장 p.N]` / `[7보충 p.N]` | 모든 개념 블록·박스·예에 |

- 원본 오타·불일치는 고치지 않고 해당 줄 바로 아래 `> ⚠ 원본 표기: … (계산하면 …)` 한 줄.
- 그림은 `[그림] 무엇` 한 줄 + 구조를 말/ASCII/표로. 그림끼리 관계는 "그림 방정식"(넓이 = 넓이 + 넓이)처럼 기호로 적는다.
- 표·수치 데이터는 원본 값 그대로 표로 옮긴다(그림에만 있는 값 포함).

## 3. 문제 설계 (3층)

| 층 | 위치 | 내용 | 풀이 |
|---|---|---|---|
| [예] | 본문, REMARK/박스 직후 | PPT 예제 전부 + 부족하면 1단계 확인 예 | 접기(풀이·답 각각) |
| 예제 01~ | Theme 끝 | 자작 3~7문제. 순서: 공식 대입 → 역적용(미지수·n 구하기) → **해석·서술형**(통계와사회 특성) | 접기. 풀이 첫 줄 = "무엇을 쓰는가"(모수·분포·공식 선택) |
| STEP UP | 2~3 Theme마다 | 여러 Theme 결합 3~5문제 | 접기 |

- 자작 문제는 **원본 개념·원본 분포표 값만으로** 풀리게 한다(원본에 없는 z·t·χ² 값 사용 금지).
- 해석형 답안은 "모범 답안 문장" 1~2문장으로 제시.
- 문제 머리에 `(쓰는 개념: …)` 한 줄을 붙여 개념-문제 연결을 명시(시발점의 근접성 연결을 보강).

## 4. 장 끝 장치 (시발점 약점 보완, 필수)

1. **정리 박스 모음** — 본문 박스를 번호 그대로 한 표/목록으로(복습 시 박스만 훑기).
2. **판단 흐름도** — "어떤 공식을 쓰나" 분기도(ASCII).
3. **수치표 모음** — 이 장에 나온 z·t·χ² 값 전부.
4. **오개념 체크** — REMARK 제목을 OX 문장으로 바꿔 8~12문항, 답·이유는 접기. 각 문항 끝에 돌아갈 REMARK 번호.
5. **원본 표기 확인 목록** — 본문 ⚠ 를 한곳에 모음(시험 때 혼동 방지).

## 5. 노션 변환 시 주의

- `<details><summary>` → 노션 토글로 변환됨. 토글 안에 수식 블록이 있으면 앞뒤 빈 줄 필수.
- 인용 블록 박스(`> **[정리]**`)는 노션 인용/콜아웃으로. 박스 안 여러 줄은 줄마다 `>` 유지, 수식 블록은 `> $$ … $$` 한 줄로.
- `aligned` 환경은 노션 블록 수식에서 지원. 인라인 수식 안 `|`는 표 셀을 깨므로 표 안에서는 `\mid` 사용.
- 헤더는 4단계(`####`)까지만. 노션은 H1~H3만 있으므로 `####` 는 굵은 문단으로 바뀜 → 세부 항목은 짧게.
- 이모지·색은 쓰지 않는다(라벨 텍스트 `[정리]` `REMARK` `[참고]` `[예]` 로 구분).
